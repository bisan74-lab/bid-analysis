# 예정가격 AI 예측 스킬

## 목적

아이건설넷 낙찰 이력 데이터에서, 각 건의 **기초금액·종목·대업종·발주처·지역·개찰일·참여업체수**만 보고
(실제 예정가격/낙찰금액은 절대 보지 않고) AI가 추론으로 예정가격을 예측한다. 그 다음 실제 예정가격과
비교해서 예측 정확도(적중률/오차율)를 계산하고, 단순 통계모델(전체 가중평균 예가율을 그대로 곱하는
기존 `recommendBid()` 방식)과 비교해서 **AI 추론이 얼마나 더/덜 정확한지** 확인하는 것이 목적이다.
(사용자가 "예정가격이 제일 중요한 데이터"라고 판단해서 만든 검증 실험.)

## 배경 지식 (추론할 때 참고할 것)

- 국내 공공입찰(소액수의/적격심사)의 예정가격은 "기초금액"을 기준으로 **복수예비가격**(보통 후보 15개
  중 4개를 추첨해서 평균) 방식으로 결정되는 준-랜덤 값이다. 통계적으로 기초금액의 평균 99.9% 근처
  (±2~3% 정도 변동)에 분포한다 — 이 프로젝트의 `webapp/lib/analysis.js`가 계산한 실측 평균은
  `예가율(예정가격÷기초금액) 평균 ≈ 0.9989`, 표준편차는 작음.
- 이 추첨 매커니즘 자체는 발주처/종목과 무관하게 설계된 것이라, **원칙적으로는 발주처나 종목별로
  체계적인 차이가 없어야 정상**이다. 다만 실제로는 발주처마다 반복적으로 쓰는 기초금액 산정 방식이나
  버림/반올림 관행 차이 때문에 미묘한 편차가 있을 수도 있다 — 이게 AI가 전체평균보다 더 잘 맞출 수
  있는 유일한 여지다. **없는 패턴을 억지로 만들어내지 말 것** — 정말 없으면 "전체평균과 비슷하게
  예측했다"고 솔직하게 남기는 것이 맞다.

## 파일 구조

```
webapp/data/ai-prediction/
  sample_features.json   # 예측 대상 샘플 (정답 없음, 이것만 보고 예측할 것)
  answers.json            # 정답(실제 예정가격/낙찰금액) — 채점 전까지 열어보지 말 것
  predictions.json        # AI 예측 결과 누적 저장 (이어하기 지원)
  score_report.json       # 채점 결과 (score-ai-predictions.js 실행 후 생성)
webapp/scripts/
  sample-for-ai-prediction.js   # 샘플 생성 스크립트 (이미 실행됨, 재실행하면 샘플이 바뀌므로 주의)
  score-ai-predictions.js        # 채점 스크립트
```

## 절차 (매 실행마다)

1. `webapp/data/ai-prediction/sample_features.json`을 읽는다.
2. `webapp/data/ai-prediction/predictions.json`이 있으면 읽어서, 이미 예측 완료된 `posting_id`는 건너뛴다
   (없으면 빈 배열로 시작).
3. 아직 예측 안 된 항목 중 **이번 배치에서 20~30건 정도**를 골라, 각 건에 대해:
   a. (선택) 같은 발주처 또는 같은 종목/대업종의 다른 과거 사례들을 `data/raw/*.csv`나 이미 아는
      맥락에서 참고해서, 사정률(예정가격÷기초금액) 경향을 살펴본다.
   b. 위 정보를 종합해서 예정가격을 **원 단위 숫자로** 예측하고, 한 줄짜리 근거를 남긴다.
   c. 특별한 근거가 없으면 억지로 만들지 말고 "발주처/종목 특이사항 없음, 전체 평균 예가율 적용"처럼
      솔직하게 남긴다.
4. 예측 결과를 `{posting_id, 예측예정가격, 근거}` 객체 배열로 만들어 `predictions.json`에 **append**한다
   (기존 예측을 덮어쓰지 않고 합쳐서 다시 저장).
5. 샘플 전체가 채워지면(또는 사용자가 그만하라고 하면) `node webapp/scripts/score-ai-predictions.js`를
   실행해서 실제값과 비교 — MAE/MAPE, 오차율 구간별(±0.5%/±1%/±2%/±3%) 적중 건수, 그리고 기존
   통계모델(`recommendBid` 방식, 전체 가중평균 예가율 적용) 예측과의 비교표를 만든다.
6. 진행상황(몇 건 완료, 다음에 뭘 할지)을 사용자에게 짧게 보고한다.

## 절대 하지 말 것

- **`answers.json`이나 원본 CSV에서 해당 posting_id의 실제 예정가격/낙찰금액을 미리 열어보고 베끼는 것.**
  `sample_features.json`에는 애초에 정답이 들어있지 않으니, 다른 파일을 열어 정답을 확인한 뒤 예측하는
  행위는 이 실험 전체를 무의미하게 만든다.
- 한 세션에서 무리하게 전체 샘플(100~200건)을 다 하려고 하지 말 것 — 배치(20~30건)로 나눠서 진행하고,
  중간에 진행상황을 보고할 것.
